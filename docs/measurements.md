# 指标如何读

- **60 fps 是吞吐，不是延迟。** 16.7 ms 是名义帧间隔。实测 59.9 fps 是程序处理速度；没有额外用逐帧计数画面验证源端每张图像都不同。
- **`frame_ms`** 是 `VideoCapture.read()` 返回后到当帧推理及后处理结束的时间，不含上游 HDMI 等待，也不含随后 HID 写入。
- **`feedback_ms`** 是板端提交位移到读到可被控制器确认的反馈帧之间的间隔；不是纯采集、USB 或游戏延迟。`-1` 表示该帧没有测到有效反馈。
- **`sent` / `hid_reports`** 分别表示有没有成功写入移动报文和这一次写了几个移动包。**`fired`** 表示按下/释放报文写入成功，不代表游戏命中，不代表接收端已经处理。
- **`feedback_timeout`** 表示原移动未被画面确认，计算基准已切换为当前帧。此前曾测试无等待的逐帧拉枪，会因反馈延迟而过冲，未纳入发布版本。

1080p60 原型中，直接采集 NV12 能稳定出帧，但整帧转 BGR 的路径曾使 QMMF 相机服务退出。不应通过反复重启或强改采集帧率来掩盖这个问题；先用 `--hdmi` 确定采集是否出帧，再区分推理和 HID。没有对每个 QMMF/固件版本做长期测试。
